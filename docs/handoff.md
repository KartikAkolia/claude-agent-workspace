**IPv6 disabled host-wide (2026-10-01).** This uses the same approach as the Debian install (`docs/homelab-networkmanager-plan.md`). The new `/etc/sysctl.d/90-disable-ipv6.conf` sets `disable_ipv6 = 1` for `all` and `default` and `0` for `lo` (the `lo` line has to come last, because writing `all` also flips `lo`). The new `/etc/gai.conf` restates the RFC 6724 precedence table with `::ffff:0:0/96` raised to `100`, so IPv4 is preferred. Neither file existed before, so there are no backups; log `/var/tmp/ipv6-off-20261001.log`. Verified live: `disable_ipv6` is `1` on `all`, `default`, `br0`, `enp4s0`, `virbr0` and `wlp3s0`, and `0` on `lo`. The only IPv6 address left is `::1`, there are no IPv6 routes, `getent ahosts` returns only IPv4, and HTTPS still works. sshd and LLMNR still listen on both `0.0.0.0` and `[::]`. Persistence at boot (applied by `systemd-sysctl`) is config inspected only. Any new NetworkManager profile defaults to `ipv6.method auto`, which re-enables IPv6 on its interface, so set `ipv6.method disabled` on new profiles, including any future Wi-Fi one. To roll back, run `pkexec rm /etc/sysctl.d/90-disable-ipv6.conf /etc/gai.conf && pkexec sysctl -w net.ipv6.conf.all.disable_ipv6=0 net.ipv6.conf.default.disable_ipv6=0`.

**Boot no longer blocks on `br0`; slow reboots traced to legacy `libvirtd` (2026-10-01) — reboot pending.** This boot's userspace took 40 s. `br0` got its port at 10.1 s but no carrier until 40.6 s, which is STP's two 15 s forward-delay phases. `NetworkManager-wait-online` waited through all of it, and `plymouth-quit-wait` waited on `network-online.target` through `remote-fs.target` → `nfs-client.target` (no NFS mounts are configured; the chain comes from the default units). The `bridge.stp no` change above removes that gap. The slow reboot in an earlier boot (30 s) wasn't NetworkManager: the legacy monolithic `libvirtd.service` hung for 30 s, then logged `Make forcefull daemon shutdown`, and NetworkManager stops after it. Both legacy `libvirtd` (enabled by hand; Fedora's preset is disabled) and the modular `virtqemud`/`virtnetworkd` daemons were enabled. Shutdowns where legacy `libvirtd` hadn't started took under 4 s. Kartik ran the fix script himself with `pkexec` (log `/var/tmp/boot-net-20261001.log`), because auto mode blocked Claude from running it:

- New drop-in `/etc/systemd/system/NetworkManager-wait-online.service.d/10-timeout.conf` sets `NM_ONLINE_TIMEOUT=10` (default 60), so boot carries on after at most 10 s even if `br0` is down.
- `connection.autoconnect-retries 0` (retry forever) on `br0` and `Wired connection 1`, so a `br0` that fails at boot keeps retrying in the background instead of stopping after 4 attempts.
- Disabled `libvirtd.service`, `libvirtd.socket`, `libvirtd-ro.socket` and `libvirtd-admin.socket`. Through `libvirtd.service`'s `Also=` lines this also disabled the `virtlogd`/`virtlockd` sockets (plus their `-admin` sockets), which the modular daemons use. Those four were re-enabled straight away to match Fedora's preset. Nothing broke in between, because `virtqemud.service` has `Requires=virtlogd.socket` and `Wants=virtlockd.socket`.

Verified live: the drop-in is loaded (`Environment=NM_ONLINE_TIMEOUT=10`), retries read `0` on both profiles, legacy `libvirtd` is inactive and disabled, all modular sockets are enabled, `virsh -c qemu:///system` lists `br0net` and `default` (both active) plus `win11`, `br0` is connected, and no units have failed. A domain named `archlinux` ran under `virtqemud` at 17:19 but was already missing from `list --all` before these changes.

**Post-reboot verification:** run `systemd-analyze` (userspace should drop well below the earlier 40 s) and check `journalctl -b -u NetworkManager | grep -E 'carrier: link connected|dhcp4 \(br0\)'` (`br0` carrier should arrive within a few seconds of `enp4s0` attaching). Expect `cat /sys/class/net/br0/bridge/stp_state` → `0`, `sysctl net.ipv6.conf.all.disable_ipv6 net.ipv6.conf.lo.disable_ipv6` → `1` and `0`, `ip -br addr show br0` → only `192.168.0.222/24`, `systemctl is-active libvirtd` → `inactive`, `virsh -c qemu:///system net-list` showing both networks active, and `systemctl --failed` empty. For the shutdown side, check that `journalctl -b -1 -o short-precise | grep -E 'System is (rebooting|powering)|Journal stopped'` shows a few seconds between the two lines, not 30. To test boot without the bridge, unplug the cable and reboot: the login screen should appear about 10 s after NetworkManager starts, and `NetworkManager-wait-online` will show as failed (expected). Rollback: `pkexec rm -r /etc/systemd/system/NetworkManager-wait-online.service.d && pkexec systemctl daemon-reload`, `pkexec nmcli connection modify br0 connection.autoconnect-retries -1` (same for `Wired connection 1`), and `pkexec systemctl enable libvirtd.service` (which re-enables its sockets too).
